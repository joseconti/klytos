# DR-008 — The Consent prototype contradicts the delivery's own strictest rule, twice

Status: drafted — NOT sent
Raised: 2026-08-10, Phase 4 Step 4, stage 5 batch B screen 4 (manifest entry 25), D-092
Blocks: nothing. Entry 25 is built, driven and shipped against the SPEC.

---

## What the delivery says, in two normative files that agree with each other

**`SPEC/manifest.md` §25**, and it says this about itself:

> Delta — **the strictest rule in the bundle**: the banner preview and the shipped banner must
> have "Reject all" at the same prominence, size and component as "Accept all". The configuration
> screen offers **no** option to make reject less prominent; that option does not exist.

**`SPEC/accessibility.md` §10.4**, which §25 cites:

> **"Reject all" is a control of the same prominence, size and level as "Accept all"** — same
> component, same size, no ghost button, no colour trick.

## What the prototype draws

`screens/Klytos Admin - Screens 4.dc.html`, the Consent screen, draws **both of the things those
two sentences forbid**:

1. **The preview's buttons are different components.** In the preview card:

   ```
   Button variant="secondary" … Rechazar
   Button variant="secondary" … Preferencias
   Button variant="primary"   … Aceptar
   ```

   Accept is `primary` and Reject is `secondary`. That is not a near miss or a rendering
   accident — it is exactly the "no ghost button, no colour trick" case, drawn on the one screen
   whose entry calls the rule strictest.

2. **The configuration card offers the option the manifest says does not exist.** `consentToggles`
   in the same file lists, as the second of four switches:

   ```
   { label: 'Reject is as prominent as accept',
     hint: 'Required in the EU — both buttons same size', on: true }
   ```

   A switch is a thing that can be turned off. The hint even states the legal requirement while the
   control offers to breach it — and a site owner under commercial pressure is precisely the person
   who would turn it off.

## What the build did, and why

**It followed the SPEC and not the drawing**, on this project's own recorded precedent: D-074, where
`SPEC/navigation.md` beat every prototype's `navGroups` because a normative SPEC file outranks a
drawing. Here two normative files agree with each other and only the prototype disagrees, so the
reading is not close.

Concretely, in `installer/admin/consent.php` and `installer/core/assets/consent-manager.js`:

- Reject and Accept carry **one class each way** — `k-btn k-btn--primary` in the preview,
  `cm-btn cm-btn-choice` in the shipped banner — with `min-width` on the shared rule, so the two are
  the same component at the same size even though "Accept all" and "Reject all" are different lengths
  in all 20 catalogues. Asserted by reading class list, box, weight and colour out of the browser.
- The prominence rule renders as a **statement**, a `<p>`, and a test asserts it contains **no
  control at all** — so the prototype's switch cannot arrive later without failing.

## What is asked of Design

Not a redesign. Correct the drawing so it stops contradicting the two SPEC files:

1. **Redraw the preview's Reject and Accept as the same component at the same size.** Either both
   `primary` or both `secondary` — the build chose both-prominent, and will follow whichever Design
   states, as long as they match.
2. **Remove the "Reject is as prominent as accept" toggle** from `consentToggles`, or confirm
   explicitly that §25's sentence is wrong and the option is intended — in which case §25 and §10.4
   both need changing, and that is a much larger conversation about what this product promises.
3. While there: the prototype's remaining three toggles ("Ask before any non-essential cookie",
   "Remember the choice for 6 months", "Show a floating re-open button") are **not backed by any
   stored setting** and were not built. Two of them are close to fields that do exist
   (`enabled`, `cookie_days`); the floating re-open button exists nowhere. Please say which are
   meant to be real settings so they can be scheduled rather than guessed at.
