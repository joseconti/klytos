# DR-012 — The Dashboard's *Next steps* panel is named and never specified

**Status:** drafted 2026-08-11 · **NOT SENT** — sending is the user's call
**Raised by:** D-110 (Phase 4 Step 4, stage 7 slice 1 — manifest entry 44)
**Blocks:** nothing. Entry 44 is built, and its working-site body is the widget
grid, which §44 specifies in full.

## What is missing

`SPEC/manifest.md` §44 names the screen's primary panel in one line:

> - Panel: *Next steps* (working site) or *Set up the site* (new site) — see the empty state

Everything that follows specifies the second. **The *Set up the site* panel is
specified completely** — three ordered steps, their sentences, their actions,
their state words, the `Later` step's disabled action with its reason, when the
panel appears and the exact moment it disappears.

***Next steps* is specified nowhere.** Not in §44, not in
`template-overview-stats.md`, not in any prototype file, and not in
`SPEC/interactions.md`. There is no statement of:

- what it contains — suggestions, recent activity, outstanding tasks, something
  else entirely;
- where its content comes from — a source in the product, or copy Design wrote;
- how many items it holds, and what happens when there are none;
- whether it coexists with the widget grid or replaces it, which matters because
  the grid is §44's own "detail cards" region and the panel is the region above
  it;
- whether it is ever dismissible, which the *Set up the site* panel answers for
  itself and this one does not.

## Why the build did not fill it in

Phase 4 rule 2: a missing value, state, behaviour, asset or copy is never made
up. The screen has a complete, specified body for a working site — the widget
grid — so nothing is broken by the absence and nothing needed inventing. What
would have been invented is a whole panel with its own content model.

## What the build did instead

Entry 44 renders, on a working site: the banner (conditional), the five stat
cards, and the widget grid. On a new site it renders the *Set up the site* panel
in place of the grid, exactly as specified, and the panel disappears the moment
the third step completes.

## What we are asking Design for

Please specify the *Next steps* panel, or tell us it should not exist:

1. **Its content.** What are the "next steps" on a site that is already
   working? Name the items, or name the source they are derived from.
2. **Its empty state.** A working, healthy, fully configured site presumably has
   no next step. §2's rule is that a good empty state must read like an answer,
   not a gap — what does this one say?
3. **Its relationship to the widget grid.** Above it, or instead of it? §44
   describes the grid as the detail-cards region and this as the primary panel,
   which suggests both — please confirm.
4. **Its bounds.** How many items, and what happens beyond that number.
5. **Or: delete the phrase.** If the panel was a working note rather than a
   requirement, saying so closes this in one line and the widget grid stands as
   the working-site body.
