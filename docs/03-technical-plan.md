## 2b. Change map — what a change of each type MUST touch

> Keel v4.0.0 §4b. Built 2026-07-28 from the change types this project has actually performed across
> six sprints, not from a generic list. **Read the row for your change type BEFORE starting it.** The
> failure this prevents is the characteristic one here: changing one side and forgetting the other
> four, in a codebase that has a public API, a 20-locale translation layer, an MCP surface, a
> capability matrix, a released installed base and in-product guides.
>
> Every artifact named is a real path or a real command. A change type discovered in a slice **adds
> its row in that slice**, never later. Verified at each test point ("did this slice touch everything
> its row names?") and at the Phase 7 gate.

| Change type | Touch always |
|---|---|
| **New user-facing string** | `__( 'domain.key' )` at the call site · the key added to **all 20** catalogues in `installer/core/lang/` in the SAME change (the locale-catalogue parity check in `scripts/keel-verify` enforces it) · never concatenate for plurals |
| **New public function / method / class** | the surface itself · `docs/api/` entry with a **runnable** example · its `docs/api/INDEX.md` row · a unit test · PHPDoc + GPL header · the `api-ergonomics` rubric pass (D-066) |
| **Changed public signature** | the same `docs/api/` entry updated — params, return, errors, permissions, behaviour — and its example **re-run** · the INDEX row · every other doc whose example calls it · a `docs/decisions.md` entry when the surface was already released (Klytos has installs: this is a breaking change, not a tidy-up) |
| **Removed public surface** | never a silent delete. Never released → entry and INDEX row deleted in the same slice. Released → entry kept, marked deprecated/removed with its version and its replacement, INDEX row reflecting that, plus a `docs/decisions.md` entry |
| **New hook or filter** | the `klytos_do_action` / `klytos_apply_filters` call site · its docblock naming every argument · `docs/api/` entry + INDEX row · a test asserting it fires with the documented arguments · **and the L-019 check: if the doc says the result is logged, audited or notified, name the listener that writes it — or state plainly that core subscribes nothing** |
| **New MCP tool** | registration in the right `installer/core/mcp/tools/*.php` · its capability in the central map (default-deny, D-046) · honest annotations (a tool that writes is never advertised read-only) · `inputSchema` with exhaustive enums · `docs/api/` entry + INDEX row · the tool count in `docs/reference/mcp-authorization.md` · an authorization test proving the refusal · the `api-ergonomics` rubric pass |
| **New admin page or API endpoint** | `klytos_has_permission( 'domain.action' )` gate **inside** the surface, never assumed from the includer (NEW-31 is that defect) · `klytos_csrf_field()` / `klytos_verify_csrf()` on anything mutating · `nonce="$cspNonce"` on every inline `<script>`/`<style>`, no inline `onclick` · escaping at print time · a per-role test asserting BOTH a 200 for an allowed role and a refusal for a denied one (L-008) · **a stable `data-testid` on every interactive element** (v5.0.0 addressability) |
| **New capability / permission** | the central capability map · every surface that should gate on it · the per-role integration matrix · `docs/reference/mcp-authorization.md` |
| **New option or stored setting** | its default · its sanitize path · the uninstall/cleanup path · migration if an installed base already has the old shape · `docs/reference/` |
| **New or changed storage shape** | BOTH backends — `file-storage.php` AND `database-storage.php` behind `StorageInterface` · a **versioned, idempotent** migration (Klytos has production installs with encrypted data) · a test asserting the PERSISTED effect, never the migration's return value (**L-017**) · `docs/architecture.md` when Phase 6 lands it |
| **New in-product guide, or edited guide content** | `installer/core/guides/*.md` · the count in this plan's code map · `klytos_list_guides` / `klytos_get_guide` descriptions if the guide is one of the REQUIRED ones · **NEW-27 first**: the blanket `*.md export-ignore` strips every guide from the release archive, so guide work before that fix ships nothing |
| **Frontend or admin CSS/JS edited** | the source file · **Klytos ships no minified pair of its own** — measured 2026-07-28: all **90** `*.min.*` files live under `installer/admin/assets/vendor/` (TinyMCE, xterm, highlight.js, Gutenberg) and are third-party distributions shipped as the vendor publishes them, so the source-first contract does not govern them. If Klytos ever minifies its OWN assets, the pair rule and a local build script arrive with it (SKILL.md, source-first assets) · the design contract in `docs/BUILD-SPEC.md` governs the admin from D-065 on: a value that disagrees with it is a Design Request, never a build-side choice |
| **New dependency (runtime or dev)** | `docs/decisions.md` entry with the alternatives considered · licence compatibility with GPL-3.0-or-later verified BEFORE adoption · `installer/composer.json` + `.lock` (runtime) or the root pair (dev) · `composer audit -d installer` back to zero · the vendored-manifest drift guard · the support matrix if it moves a floor |
| **Bug fixed** | the fix · a test that was **observed failing before the fix** and passing after (a guard never seen failing is not delivered — **L-010**) · a `docs/lessons-learned.md` entry when the mechanism is transferable, with its `Check added` line |
| **Version bump** | every row of §5 Version touchpoints — they are currently in four-way disagreement, which is precisely why this row exists · `changelog.txt` · the release record |
| **Any commit at all** | the confidential-data scan on the staged files (UNBREAKABLE) · `docs/PROGRESS.md` and `docs/decisions.md` updated at the moment of the change, never at the end |

## 3. Conventions (observed — this is the contract for new code)

- **Naming.** Global procedural API is `klytos_*` **snake_case** (`klytos_get_option`,
  `klytos_esc_html`). Classes are `PascalCase` under `Klytos\Core` (and `\MCP`, `\Ai`, `\X402`,
  `\Cache` sub-namespaces). Methods are `camelCase` — except the helper files, explicitly exempted
  in `phpcs.xml`.
- **Style.** PSR-12 as adapted by `phpcs.xml` (ruleset name `Klytos`): line limit 150 (warning),
  9 spacing sniffs disabled so WordPress-style spaces inside parentheses are permitted —
  `foo( $bar )`, not `foo($bar)`. **This is the project's style; do not "correct" it.**
- **Hooks.** `klytos_do_action('domain.event', ...)` / `klytos_apply_filters('domain.thing', $v, ...)`.
  Names are dot-namespaced and lowercase (`page.after_save`, `admin.sidebar_items`,
  `mcp.tool_response`). Every meaningful decision fires a hook before/after; every user-facing
  string, query and response should be filterable (Keel's extensibility rule — see the gap in the
  audit for where the read path falls short).
- **Escaping and sanitization.** Output goes through `klytos_esc_html/attr/url/js/textarea`; input
  through `klytos_sanitize_*`; rich HTML through `klytos_kses` / `klytos_kses_post`. Never echo raw.
- **CSRF.** Every admin form carries `klytos_csrf_field()`; every mutating endpoint calls
  `klytos_verify_csrf()`.
- **CSP.** Every inline `<script>`/`<style>` in the admin carries `nonce="$cspNonce"` (from
  `core/auth.php:787`) or the browser blocks it. No inline `onclick`/`onchange` handlers —
  `addEventListener` inside a nonced script block.
- **Permissions.** `klytos_has_permission('domain.action')` — the live implementation is in
  `helpers-global.php:430`. **Every** admin page and API endpoint must gate on it (this is the
  single largest as-built gap; see audit S-01…S-07).
- **i18n.** `__('domain.key')` with the key added to all 20 catalogues in the same change.
- **Time.** Store UTC, display local: `klytos_gmdate` / `klytos_date` / `klytos_timezone`.
- **Comments/docblocks.** Every file carries a GPL header with `@copyright`; public surfaces carry
  a docblock. Comments in English.
- **Plugin contract (immutable).** Plugin ID = directory name = `{id}.php` = the PHP header.
  `klytos-plugin.json` is an optional extension, never the identity.

**Playground: EXISTS since 2026-07-18** (Sprint 1 slice 0) — `scripts/dev/seed-playground.php` +

authorization work testable. A MySQL/docker tier was **not** built: file storage covers Sprint 1, and
`database-storage.php` verification remains an open gap.

**Gate zero (amended by D-025).** Originally "`phpcs` clean + the app boots + one MCP `tools/list`

on 2026-07-18 (app boots; `tools/list` returned 177 tools). Evidence in `docs/05-test-points.md`.

**Never run `installer/install.php` or `installer/cli.php build` in a checkout** — both are

### 4a. Driver per surface (Keel v5.0.0 — `references/test-automation.md`)

**The rule this table serves: the user is not the test runner.** Anything a machine can drive, the
assistant drives — starts the environment, opens the screen, fills every field with valid, empty and
invalid values, clicks every control including the failure paths, asserts what the interface actually
shows, and reads back the console, the failed requests and the log. Asking the user to "go to that
screen and tell me what appears" is a protocol defect, not a test.

| Surface | Driver | Headless? | Evidence it produces | State |
|---|---|---|---|---|
| Admin panel (42 page controllers) | **Playwright** against the `php -S` playground | Yes, by default | Trace, video, screenshots, JSON report, `data/logs-*` | `[A]` — `tests/E2E/` does not exist |
| Generated public site | Playwright against the built `installer/public/` | Yes | Same | `[A]` |
| Admin JSON API (23 endpoints) | Playwright request context, or `curl` with the real `klytos_session` cookie | Yes | Status, body, headers per call | Partly `[E]` — `AdminGateHttpTest` already does this per role |
| MCP server | Scripted JSON-RPC over HTTP against the playground; MCP Inspector CLI where useful | Yes | Request/response transcript | Partly `[E]` — the integration tier drives `tools/list` and `tools/call` |
| CLI (`php cli.php <command>`) | Direct execution + output snapshot. **Never `cli.php build` in a checkout** — destructive (NEW-04) | Yes | stdout/stderr, exit code | `[A]` |
| Install wizard (`install.php`) | Not driven in a checkout — destructive (NEW-04). Driven only against a disposable copy | Yes | — | `[A]` |
| PHP unit + integration tiers | PHPUnit | Yes | JUnit/testdox output | `[E]` — 284 tests / 1385 assertions |

**Screen stealing: none.** Every surface here is web, HTTP or CLI. Playwright is headless by default
and the PHP built-in server takes no display. There is no macOS, Windows or Android UI surface in
this project, so the mitigation rows those platforms would need do not apply. **The user's screen is
never taken by a test run**, and that is a property of the stack, not a promise.

**Element addressability.** Every interactive element in the admin carries a stable
`data-testid`, in English, never translated, never the visible text — the admin ships 20 locales, so
a locator bound to visible text breaks on a language switch. Convention: `<screen>.<element>[.<id>]`
— `pages.row.14`, `login.submit`, `plugins.toggle.klytos-forms`. **Never rewrite an accessibility
label to make an element findable**: it is read aloud to a real user. Prefer role-and-accessible-name
locators where the text is stable (they assert the accessibility tree and the behaviour at once) and
fall back to the identifier where the text is content. `code-reviewer` treats a new interactive
element with no identifier as a slice defect, exactly like a missing docblock — this is a **build**
requirement, not a test requirement.

**Division of labour.** The default is that the assistant drives every flow end to end. The complete
list of legs it cannot, each with its tag:

| Leg | Tag | Steps for whoever runs it |
|---|---|---|
| A real screen-reader pass (VoiceOver / NVDA / JAWS) over the admin and the generated output | `ASSISTIVE-TECH` | The guided loop in `references/accessibility.md`, batched per flow at sprint closes — not slice by slice |
| A live AI provider call with the user's own API key (OpenAI / Anthropic / Gemini) | `CREDENTIAL` | Only the provider leg. The chat engine, the tool loop and every refusal path are driven against a stubbed provider |
| A real x402 settlement through Coinbase or Stripe | `CREDENTIAL` + `PRODUCTION-RISK` | Only the settlement leg; the gate, the bot detector and the transaction log are driven offline |
| "Is this the behaviour you meant?" on a redesigned screen | `JUDGMENT` | Asked over captured screenshots AFTER the driven test passed — never by asking the user to walk the flow to form an opinion |
| A real upgrade from a published GitHub release | `EXTERNAL-APPROVAL` (release must exist) | `scripts/dev/upgrade-test.sh` already drives the local half |

Nothing else is delegable. `JUDGMENT` on a criterion with no driven test beside it is the laziest
escape in the contract and is a defect.

**Static analysis and sniffers**, run at every test point, not once before release:

```bash
vendor/bin/phpcs --standard=phpcs.xml            # baseline-locked per D-025
php -l <every touched file>
composer audit -d installer                       # must stay at zero (D-052)
vendor/bin/phpstan analyse                        # [A] — phpstan.neon does not exist (T-03)
```

**Accessibility automation.** `@axe-core/playwright` inside the E2E tests, run **per state** and not
per page — the empty list, the form showing errors, the open modal, the expanded sidebar — tagged to
WCAG 2.2 AA. Plus the **driven keyboard pass**: Tab through each screen and assert the focus
sequence, with the ARIA snapshot kept as a regression artifact. Both move from the manual list to the
driven list (Keel v5.0.0). The honest boundary does not move: automated tooling finds a large share
of issue volume and far less of the success criteria — alt-text quality, reading order, link purpose
out of context and real screen-reader behaviour stay `ASSISTIVE-TECH`.

**Read-back duty.** A screen that looks right while throwing has not passed. Every driven test
subscribes to `console`, `pageerror`, `requestfailed` and `response` (flagging status ≥ 500), and
additionally reads `installer/data/logs-*/` after the flow — Klytos writes its own log there and a
PHP notice never reaches the browser. Any of them non-empty fails the test.

**Doctor rules that apply here specifically** (`references/test-automation.md`):
`--check` never needs sudo and never installs; `--plan` prints the literal command list before
anything runs; `--fix` runs it only after an explicit OK, row by row. Probe with `command -v`, never
`which`. Probe Composer through the phar, not the alias — an alias does not exist in a non-interactive
shell, which is exactly why the naive probe failed here. Never change a global runtime version
silently: PHP is MacPorts-managed and shared with the user's other projects.

on "PHP 8.1 cannot be verified through the suite" — true of PHPUnit 11, which needs 8.2+. But

tested (boot the app, run `tools/list`, exercise the install guard) even where the full suite cannot
run. Related: **L-022** records that CI's 8.2 leg has never executed because nothing is pushed —
`/opt/local/bin/php82` means that leg can be rehearsed locally before it ever reaches CI. Neither is
decided here: both are inputs to whoever plans the slice that owns D-027's revisit trigger.

## 6. Distribution and release

- **Install:** standalone `installer.php` from `https://github.com/joseconti/klytos-installer`
  uploaded to the domain root, or manual ZIP extraction + `/installer/install.php`.
- **Update:** self-updater against GitHub Releases (`core/updater.php`), with backup and rollback;
  CLI equivalent `php cli.php update:run`.
- **Packaging:** `git archive` semantics driven by `.gitattributes` alone. No build script, no
  release workflow, no version automation.
- **Known packaging defect:** the blanket `*.md export-ignore` strips `README.md` and `INSTALL.md`
  from release archives, although `INSTALL.md` instructs users to upload them (audit H-02).

## 8. Debug logging (Keel requirement — partially present)

`Klytos\Core\Logger` exists with PSR-style levels and the `klytos_log_*` helpers, plus an admin
`logs.php` viewer and `plugin.logs_enabled` / `plugin.logs_disabled` actions. What is not confirmed
`as-built, unverified`: whether there is a single documented user-facing switch, OFF by default at
release, that a user can flip to hand back a debuggable failure in one round trip. To verify and
close in the first Phase 5 sprint.
